# kirikuchi（切り口セレクター）

同じ主張でも切り口を替えると読後の温度が変わる。書き始める前に切り口を選ぶだけで、文章の質が大きく変わるため、いきなり1案を書かずに「どの言い回しにするか」を先に見せる。

7つの切り口の詳細・例・注意点は `references/techniques.md`。提案前に必ず読む。

## 流れ

### 1. 目的を掴む
依頼文から次を拾う。足りない分だけ聞く（最大1〜2問。聞きすぎない）。
- 伝えたい主張（何を言いたいか）
- 目的（理解させたい／頷かせたい／感情を動かしたい／説教臭さを消したい／違いを見せたい／行動させたい／記憶に残したい）
- 読者・媒体（X、note、社内資料、メール等）

すでに依頼から明らかなら聞かずに進む。

### 2. 切り口を提案する
`references/techniques.md` の早見表で目的に合う技法を2〜3個選び、**今回の主張に当てはめた1〜2行の見本**を付けて提示する。抽象的な技法名だけ並べない。見本があると選べるため。

形式:

```
切り口の候補:
★おすすめ ⑤天秤対比型 — 「〜は依頼でわかる。高い人は…低い人は…」
   理由: 違いを一瞬で見せたい目的に合う
  ②特徴3リズム型 — 「主語を抜き、理由を省き…」
   理由: あるあるで頷かせたい場合
  ⑥電卓型 — 「曖昧な指示1回で30分の損…」
   理由: 行動を変えさせたい場合
どれで書く？（複数選べば各案を作る）
```

おすすめは1つに絞り、理由を一言で添える。注意点（ネタが必要・作り話不可など）が効いてくる技法は、その旨も一言添える。

### 3. 文章を作る
選ばれた切り口で本文を書く。
- ④他者引用・③再現VTRは実話が要る。ユーザーから素材が出ていなければ、作り話で埋めずに素材を聞く、またはプレースホルダ（【ここに実際のセリフ】）で残す。
- ⑥電卓の数字は前提と計算式を添える。
- 複数選ばれたら、同じ主張で技法違いの案を並べる（切り口の在庫を見せるのがこのスキルの価値）。

### 4. ファイルを作る
ファイルが必要な依頼（記事・資料・レポート等）なら、選んだ切り口の文体で構成して作成する。形式は依頼に従う（md、docx等）。切り口はファイル全体の文体に反映し、章ごとに切り口を替えるなら冒頭でその旨を示す。保存先の指定がなければカレント付近に置き、パスを報告する。

### 5. レポートする
短く報告する。
- 使った切り口とその理由
- 成果物の場所（パス）
- 他の切り口で書き直せること（候補を1行）

## 無人実行・即答を求められた場合
ユーザーが確認できない状況や「おまかせ」と言われた場合は、おすすめを採用して進め、レポートに「切り口は○○を採用、理由は〜。他案が必要なら言って」と書く。確認待ちで止まらない。

## しないこと
- 選択肢を出さずに1案だけ書く（このスキルの意味が消える）
- 7つ全部を毎回並べる（選べなくなる。多くて3つ）
- 実話前提の技法で事実を捏造する
